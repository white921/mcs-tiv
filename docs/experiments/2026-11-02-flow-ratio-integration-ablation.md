# 中負荷合流における積算・終端値アブレーション

- 台帳ID: `2026-11-02-flow-ratio-integration-ablation`
- 状態: `planned`
- 位置づけ: `development`
- 開始予定日: 2026-11-02

## 目的

Eval.7交通量探索で現行提案方式`lambda=2`が山下方式を上回った
500/1000と700/1000台/時について、優位性が10秒間の速度損失積算に依存するかを
終端速度アブレーションとの直接比較で調べる。

## 仮説と事前固定

- 500/1000と700/1000では、合流判断が十分に発生する一方で網全体は完全過飽和ではない。
- AcceptとRejectの途中の減速波が10秒後に回復する場面で、積算は終端値より
  後続車害を選別できると仮説を立てる。
- 判断式、`lambda=2`、後続車集合、予測時間、車両入力は固定し、
  `integrated` / `terminal-held`だけを変更する。
- 信号放流アブレーションが全4バッチ正常終了した場合のみ、
  500、700の順で実行する。

## 条件

| 項目 | 値 |
| --- | --- |
| ケース | Eval.7 |
| 交通量 | 合流側500または700 / 本線側1000台/時 |
| Bus比率 | 25% |
| seed | `6, 8, 9, 10, 12` |
| 時間 | 300秒 |
| 判断式 | `arrival_margin + 2 * max(accept_loss - reject_loss, 0)` |
| 比較 | `integrated` vs `terminal-held` |
| 併用しない機能 | 反復拒否待ち、承諾リース、早期合流、2段階交渉、priority hold |
| 環境 | Ubuntu `sgnlab`、Python 3.15.1、SUMO 1.28.0 |
| 並列数 | 各方5、合計10 SUMO |

## 評価と限界

- seed対応の平均速度差を主に、停止、流出、急減速、物理衝突、承諾率を併記する。
- 判断不一致と、終端速度差が小さいのに積算損失差が残る交渉を抽出する。
- この交通量とseedは既存探索で使用済みであり、結果は積算の寄与切り分けに
  用いるdevelopment診断とする。最終的な方式優位性の確認には使わない。
