## 目的と独立な変更

1秒の承諾信号だけの再利用で最悪のseed 6を改善できなかったため、別の変更として
同じ送信車・同じ衝突領域の参加車両集合だけを1.0秒安定化した。

- 新しく検出された衝突車両は集合に追加
- 代替軌道は毎回最新状態から再生成
- 古い軌道・速度指令・優先関係は保持しない
- 承諾信号リース、早期交渉、反復拒否待ち加点は併用しない

固定条件はEval.7、300/1000台/時、seed 6/8、300秒、山下方式/提案`lambda=2`、
workers=1、Ubuntu Python 3.15.1 / SUMO 1.28.0である。

## 結論

参加車両集合の1秒安定化は採用しない。取消と車両73の停止を減らしたことは、
交渉集合の入れ替わりが不安定化の一因だったことを示す。しかし事前基準の「両seedで
問題停止と取消を減らし、速度・急減速を悪化させない」は満たさなかった。
追加検証に進む前に、合流を実行可能な一つの取引として完了させるルールの設計が必要である。

## 限界

- 問題が出た2 seedのみの改善用診断で、一般的な優位性は示さない。
- 参加集合の継続は最新の衝突車両を追加するため、集合拡大と停止列悪化の因果は未分離である。
- 速度改善と総停止時間が同じ方向に動かないseed 8は、停止車両の内訳が影響している。
