# 参加車両集合の短時間安定化パイロット

## 状態

- 状態: planned
- 種別: 改善用の小規模診断
- 実行日: 2026-11-01

## 目的

Eval.7の合流側300台/時・本線側1000台/時で悪化したseed 6・8について、
交渉相手の経路IDが更新されたたびに交渉全体が取り消されることが、車線端停止の
一因かを調べる。

1秒の承諾信号だけを再利用した前実験では最悪のseed 6を改善できなかったため、
今回は別の変更として、同じ送信車・同じ物理衝突領域に対する参加車両集合を
1.0秒だけ一つの交渉として扱う。

## 変更内容

- 同じ送信車・同じ衝突領域の交渉に限り、最初の参加車両集合を1.0秒保持する。
- 更新後に新たに見つかった衝突車両は集合へ追加する。
- 代替軌道は毎回、最新状態から再生成する。古い軌道・速度指令・優先権は保持しない。
- 既に得た承諾は、同じ交渉集合に属する間だけ保持する。
- 最新状態で代替軌道が生成できない場合は継続せず、従来どおり再判断する。

承諾信号リース、早期交渉開始、反復拒否待ちの加点は併用しない。

## 固定条件

- case: Eval.7
- 合流側/本線側: 300/1000台/時
- seed: 6, 8
- 時間: 300秒
- 比較方式:
  - 山下方式
  - 後続車影響を使う改善提案、`lambda=2`
- 参加車両集合の保持: 1.0秒
- 固定入力: 既存の同一300/1000入力を使用
- Python/SUMO: 3.15.1 / 1.28.0

## 比較対象

- 同一seed・同一入力・参加車両集合保持なし
- 参考として、採用しなかった承諾信号1秒リース

## 事前の採否基準

両seedで、問題車両の車線端停止時間と`desired_path_disappeared`取消が減り、
物理衝突・急減速・全車平均速度を悪化させない場合だけ次段階の候補にする。
片方だけ改善、または山下方式と提案方式で副作用が反転する場合は原因診断に限定する。
