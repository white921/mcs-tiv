# 実験台帳

このディレクトリを、シミュレーションの目的・条件・結果・研究判断・Git系譜を
後から追跡するための索引とする。数値と実行環境の機械的な正本は
`results/runs/<experiment-id>/`配下のmanifest、metrics、ログであり、台帳はそれらを
置き換えない。

## 証拠の優先順位

1. 各case/seedの`manifest.json`、`evaluation-metrics.json`、ログ
2. バッチの`experiment-manifest.json`、`summary.json`、`runner.log`
3. この台帳の実験記録
4. 会話、コミットメッセージ、作業メモ

数値が食い違う場合は上位の証拠を確認し、台帳を訂正する。過去実験を比較・引用する
ときは、必ず対応する実験記録とmanifestを確認する。

## Git SHAの区別

- **実行ソース**: manifestの`git.commit`。シミュレーションを開始したコード。
- **結果コミット**: 正常終了した実験ディレクトリだけを追加した専用コミット。
- **記録コミット**: 結果の解釈、限界、採否を台帳へ反映したコミット。

実行開始時にdirtyだった実験は、実行ソースSHAだけでは完全に復元できない。正式対照は
原則としてcleanなworktreeから実行し、dirtyな結果を使う場合は保存済みsourceとhashを
含めて限界を明記する。

## 運用

### 実行前

1. [`template.md`](template.md)から1バッチ1記録を作る。
2. `planned`または`running`として、目的、仮説、比較対象、固定条件、採否基準を書く。
3. 一覧へ追加し、`python3 scripts/audit_experiment_ledger.py`で状態の一致を確認する。

### 正常終了後

1. 全Runの`exit_code: 0`、`source_unchanged: true`とバッチの正常完了を確認する。
2. runner/stdout/stderr/SUMOログ、必須artifact、物理衝突、既知警告を確認する。
3. case別・seed別の主要指標と比較対象との差を書く。
4. 結果ディレクトリだけを専用commitでpushし、結果コミットSHAを記録する。
5. 結論、限界、採否、次の判断を記録し、この一覧の状態を更新する。

失敗・未完了実験も削除せず、`failed`または`incomplete`として原因と再利用できない
範囲を残す。ただし失敗・未完了の結果はpushしない。
